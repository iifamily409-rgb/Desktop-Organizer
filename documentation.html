Installation

Desktop Organizer is a single Windows executable. An Electron shell provides the interface and a local Python engine does the file work; the engine's API listens on 127.0.0.1 only, so nothing is reachable from your network. The app works fully offline except for the AI provider calls you choose to configure.

  • System: Windows 10 or 11, 64-bit.
  • Installer: Desktop-Organizer-Setup-v1.0.2.exe, 108.7 MB, NSIS.
  • Privileges: per-user install. No administrator rights are required.
  • Removal: Settings > Apps > Desktop Organizer.
  • Licence: MIT. Free, no account, no activation, no telemetry.

Run the installer and complete the short setup wizard. The app launches afterwards and begins watching Desktop and Downloads immediately. Your SQLite database, logs and chat history are written to the app data folder inside your Windows user profile, so they sit on your machine with your files.

SmartScreen may interrupt the first run

Code signing is not in place for v1.0.2. If Windows reports that the app is not commonly downloaded, click More info and then Run anyway. The build is reproducible from the public repository, and MIT licensed.

Getting started

Everything starts from the left sidebar. Eight screens, one engine behind them:

  • Dashboard — watched folders, live counters and the scan cards.
  • Files — the File Manager view of what the engine can see.
  • Organizer — run filing on chosen paths and read the history.
  • Search — find files across the folders you watch.
  • Cleanup — duplicates, large files and the Downloads review.
  • Security — the app's own safety controls.
  • Assistant — the AI workspace and provider profiles.
  • Settings — monitoring, library, startup, appearance and data.

Folders the engine watches are called monitor roots. Desktop and Downloads are enabled by default; Documents, Pictures, Videos and Music are opt-in. Settings lets you add up to 12 additional custom watched folders on top of those.

Three things decide most first-run behaviour: which roots are enabled, whether Auto-organize enabled is on, and whether you want a central library instead of sorting in place. Set those and the defaults are sane for the rest.

Closing the window does not quit the app

Desktop Organizer keeps running in the tray. The tray menu offers Open Desktop Organizer, Organize All, Show recent activity and Quit Desktop Organizer. Windows hides new tray icons in the overflow area by default, so drag the icon onto the taskbar if you want it visible.

Desktop organization

The Organizer page runs on the paths you select or on all folders at once, with a quick action per folder and an Organize all button when you want everything filed in one pass.

Files are routed into one of eight categories: Documents, Images, Videos, Music, Archives, Code, Installers and Others. Others is the residual bucket for anything that does not match one of the named types.

By default files are sorted in place inside the watched folder. Switch on Use one central library in Settings and pick a Library location, and the app creates an OrganizerLibrary folder with a subfolder per category; everything then lands there instead. One library is easier to back up and to point a launcher at; sorting in place keeps your existing shortcuts working.

When a destination already holds a file with the same name, the Existing file strategy decides what happens:

  1. Rename to file (1).ext — the default; both copies survive.
  2. Skip it and leave it where it is — the source stays put.

Every move is reversible

Organization History lists each run with the original path and the destination path for every file in it. Undo moves reverses recorded moves, and Undo this batch rolls back a single run without touching later ones.

Downloads organization

Downloads is the awkward folder: files arrive in pieces and rename themselves as they finish. The engine therefore waits for a file to stop changing before it moves anything, and it never touches an extension that signals an incomplete transfer.

Timing is controlled by three settings, all in Monitoring:

  • File stabilization delay (seconds) — default 2, range 0 to 300. How long a file must sit unchanged before it counts as stable.
  • Download completion delay (seconds) — default 10, range 0 to 600. Extra quiet time after a download before filing.
  • Scan interval (seconds) — default 60, range 15 to 3600. How often the scheduled scan runs.

Alongside them are Auto-organize enabled, Enable real-time monitoring and Enable scheduled scan. Real-time monitoring reacts as files land; the scheduled scan is the safety net that catches anything missed while the app was closed.

These extensions signal an unfinished transfer and are left alone: .crdownload, .partial, .part, .download, .opdownload and .tmp.

The Dashboard tells you what the engine is waiting for. Waiting to settle counts files still inside the quiet window, Filed in real time counts what has been routed, Files detected and Folders watched give the rest of the picture.

Pick your delays to match your connection

Slow or chunked downloads need a longer Download completion delay (seconds). Large archives that grow for minutes need a longer File stabilization delay (seconds). Both are conservative by design: waiting costs nothing, moving a half-finished file does.

To keep the folder tidy without you, turn on Start with Windows and Organize on startup. Windows notifications controls whether each run announces itself; v1.0.2 removed the duplicate and noisy notifications that earlier builds produced. Theme sets light or dark.

Duplicate cleaner

The Cleanup page groups duplicates by comparing file contents in chunks. Names are not evidence: two files called report-final.pdf can differ, and a copy renamed to report(1).pdf can be byte-identical to the original. Only content matches are shown as duplicates.

How the page works:

  • Grouped results — each group lists every identical copy found.
  • Sorting — order by Size, Date or Name to decide which copy to keep.
  • One kept by default — each group retains a single copy unless you change the selection.
  • Recycle Bin only — confirmed removals are sent to the Recycle Bin. There is no permanent deletion path in the app.

Three more tools sit next to duplicates: Large files for what is eating disk space, Downloads review for installers and archives you no longer need, and an Ignored list for files you want excluded from future scans. The Dashboard mirrors the same checks as scan cards: Duplicates, Large files, Downloads and Hidden.

Check the kept copy before you confirm

Content matching is exact, but your choice of which copy stays is yours. Verify the folder and filename you are keeping, especially for versioned documents, photos with sidecar files, or anything inside a synchronised folder. Emptied Recycle Bin contents are outside the app's control.

AI Assistant

v1.0.2 rebuilt the Assistant as a chat workspace rather than a text box. The chat sidebar holds every conversation, with chat search, rename, archive, pinning, auto-generated chat titles and history management. You can attach files to a chat, and export any conversation to TXT, Markdown, PDF or JSON.

Anything the Assistant can do to your files is labelled with a safety class before you agree to it:

  • Read only — inspects, changes nothing.
  • Launches something — opens an application or a file.
  • Changes files — moves or organizes, recorded in history.
  • Deletes files — needs explicit confirmation and routes to the Recycle Bin.

The Assistant is local-first

The engine and its API run on 127.0.0.1. Chat history and provider keys stay in the app data folder in your user profile. The app is usable with no provider attached: only the calls you make to a provider leave the machine, and file organization never depends on one.

Provider profiles

A profile is one provider plus one model plus one key, saved under a name you choose. You can keep several and switch between them without losing data — a cheap model for everyday questions, a stronger one for longer work, a local one for anything sensitive.

Profile management:

  • Multiple saved profiles with per-profile model selection.
  • Switch provider without losing chats or settings.
  • Test profile to check the connection before you rely on it.
  • Duplicate and delete for building variants or clearing dead ones.
  • Reset removes all AI profiles, keys and chats.

Supported provider kinds:

  • OpenRouter
  • OpenAI
  • Google AI Studio
  • Anthropic
  • LM Studio
  • Ollama
  • A custom OpenAI-compatible endpoint

Until a profile is configured, the Assistant has no model to talk to. As the app puts it: “Open Provider settings below and add OpenRouter, OpenAI, Google AI Studio, Anthropic, LM Studio, Ollama or your own endpoint. The chat unlocks as soon as it has a key and a model.”

Reset is destructive

Reset clears every profile, every stored key and all chat history in one action. Export the conversations worth keeping first — TXT, Markdown, PDF or JSON all work — and use delete on a single profile when you only want to retire one.

Custom providers

The custom kind points the app at any OpenAI-compatible endpoint. If your server speaks that API, it works here: a self-hosted gateway, a company proxy, a model host that is not in the built-in list. Give it the endpoint, the key and the model name, then run test profile to confirm the round trip before you start a chat.

Two rules apply whatever you connect:

  1. The chat unlocks as soon as the profile has a key and a model. Missing either one leaves the Assistant idle rather than guessing.
  2. Keys and profile settings are stored locally. There are no bundled credentials and no hidden uploads; only the prompt text you send reaches the provider you configured, and file contents are attached only if you include them.

For a model that never leaves the machine, choose LM Studio or Ollama instead of a remote endpoint. Those profiles talk to a server on your own PC, so prompts, attachments and responses stay local end to end. It is the option to use for folders holding contracts, financial records or client material.

Fully offline is a supported configuration

Run the app with no provider at all, or with a local LM Studio or Ollama profile, and nothing needs an internet connection. Organization, cleanup, search and history are all handled by the local engine.

Desktop Copilot

Desktop Copilot is the help surface inside the Assistant. Ask it a question and it answers about the screen and folder you are currently looking at, rather than giving you generic instructions for a screen you are not on.

That makes it useful for:

  • What a setting on the page you are reading actually changes.
  • Why a particular file was skipped, deferred or renamed.
  • Planning a run over the folder in front of you before you commit to it.
  • Finding the command you want, in words, instead of hunting through menus.

It is not a separate product and does not have separate privileges. Copilot runs on the same provider profile you have selected, and its actions carry the same safety classes: Read only, Launches something, Changes files, Deletes files. Destructive actions still need your explicit confirmation and still go to the Recycle Bin.

Context follows privacy rules

Screen context is assembled locally and sent only as part of a prompt to the provider you configured. For sensitive folders, switch to a local LM Studio or Ollama profile before asking Copilot about what is on screen.

Command palette

Press Ctrl + K anywhere in the app. Type a few characters, pick an entry, and it runs. Entries are grouped by what they touch.

  • AI — New chat, Open AI history.
  • Organize — Organize Desktop, Organize Downloads, Organize every watched folder.
  • Folders — Open Downloads, Open Desktop.
  • Cleanup — Find duplicates.
  • Go to — Open File Manager, Open Settings, Open Organizer.

Each entry runs the same action as the button on its page; the palette is a shortcut, not a second implementation. When a run finishes you get a result toast, such as N file(s) organized in Downloads or Downloads was already tidy. Nothing was silently done, and nothing was silently skipped.

Troubleshooting

Most problems are a setting not being on, a file not being ready yet, or Windows getting in the way of an unsigned build. Work through these in order.

Nothing is being organized

  • Check Auto-organize enabled and Enable real-time monitoring in Settings.
  • Confirm the folder is a monitor root. Documents, Pictures, Videos and Music are opt-in, and custom roots are added in Settings, up to 12.
  • Run Organize all from the Organizer page, or from the tray menu, to test the engine directly.
  • Organize on startup decides whether a launch files anything at all.

Files sit unfiled for a while

  • A Waiting to settle count on the Dashboard is normal: the file is inside its quiet window.
  • Incomplete transfers keep their extension — .crdownload, .partial, .part, .download, .opdownload, .tmp — until they finish.
  • Long downloads are better served by a larger Download completion delay (seconds) than by forcing an early move.

Windows blocks the installer

  • SmartScreen: More info then Run anyway. The build is unsigned, not unsafe.
  • No administrator prompt is expected. A per-user install goes into your profile.

Tray icon or notifications missing

  • New tray icons land in the Windows overflow area. Drag the icon onto the taskbar to keep it visible.
  • Check Windows notifications in Settings, plus your OS focus settings.

The Assistant will not answer

  • A profile needs a key and a model before the chat unlocks. Add whichever is missing.
  • Use test profile to separate a bad key from a network problem.
  • Switch to another profile to confirm the chat itself is healthy.

Data, removal and known problems

Database, logs and chat history live in the app data folder inside your user profile. v1.0.2 corrected the uninstall data retention behaviour, so check what a removal leaves behind before you delete that folder by hand. The same release fixed download organization timing, notification spam, startup registration, duplicate file safety, real-time monitoring edge cases and installer reliability.

Before you report anything

Note the folder path, the file extension, your monitoring delays and whether the engine reported the run at all. That is usually enough to tell a bug apart from a file still waiting to settle.
