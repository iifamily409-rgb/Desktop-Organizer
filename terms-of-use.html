Use at your own risk

File-organising software operates on the one thing on your computer that usually cannot be recreated: your data. Moving a file changes its path, and paths matter — a shortcut, a project reference, a sync client, a build script or an application's own settings may be relying on the old location. Recategorising a folder you use daily is therefore not a risk-free act, and no amount of care in the code removes that.

Risks you should weigh before the first run

  • Applications that expect files at fixed paths may stop finding them after those files move.
  • Cloud-synced folders such as OneDrive can react to mass moves by re-uploading or re-materialising content; cloud-only placeholders may be skipped or pulled down.
  • Antivirus software may quarantine an unsigned installer; that is a false positive, but it still costs you a working installation.
  • Duplicate detection compares contents, and identical contents do not always mean identical purpose: two files may be the same bytes and still need to live in two places.
  • Real-time monitoring acts on files as they arrive, so an unusual workflow — a video project, a virtual machine image, a game mod load order — deserves a folder that is not watched.

The mitigations in the product exist to reduce these risks, not to eliminate them: files in progress are never touched, cleanup goes to the Recycle Bin rather than deleting outright, every run is recorded in Organization History with undo, and each destructive action asks for confirmation. Undos depend on the destination still being intact, so act promptly and back up regardless.

Back up first

Make a copy of anything you cannot afford to reconstruct before you let the app reorganise a folder. This is the single most useful thing a new user can do and it is a condition of sensible use, not a formality.

  • Take a fresh backup, or at minimum a copied snapshot, of the folders you are about to organise.
  • Prefer a backup you can restore from, and test a restore of one file so you know the mechanism works.
  • On a work machine, follow the organisation's backup and change process rather than inventing your own.
  • Start with one folder on a small subset, confirm the result reads correctly, then widen the scope.
  • Empty the Recycle Bin only once you are satisfied, because a recycled file is still recoverable until you do.
  • Keep Organization History available while you decide: it is the record undo relies on.

Nothing in these terms obliges you to buy any particular backup product. The expectation is simpler than that: if you have not got a second copy, you should not be running an automated move over the folder that holds the only one.

A sensible first run

Back up Downloads, enable monitoring for that one folder, leave the default stabilization and completion delays alone, organise a handful of finished files, review the preview, and check that the projects depending on those paths still open. Only then add Documents, Pictures or a custom folder.
