Windows SmartScreen warning on the installer

Open

What you see

After double-clicking Desktop-Organizer-Setup-v1.0.1.exe, Windows shows a blue “Windows protected your PC” dialog that hides the Run button.

Reason

The application is not code-signed. SmartScreen trusts executables that carry a certificate from a purchased code-signing identity and have accumulated download reputation. This build is signed only by its own hash, so every fresh copy is unknown to Windows — the warning is about the certificate status, not about the contents of the app.

Solution

  1. In the warning dialog, click More info.
  2. Click Run anyway.
  3. If your browser flagged the file instead, choose Keep / Show downloads → Keep.

Before you click anything

Confirm you got the installer from this site or the official GitHub release, and that the file is Desktop-Organizer-Setup-v1.0.1.exe at 98.2 MB with SHA-256 125436d4ca2ebbaec821229bc32041ae122c8a4b843ed28a780179e2d157572d. Verify from the folder containing the file:

certutil -hashfile "Desktop-Organizer-Setup-v1.0.1.exe" SHA256

Workarounds

  • Unblock the file: right-click it → Properties → tick Unblock → OK, then run the setup.
  • Keep the installer in a folder excluded from aggressive antivirus scans; some security suites flag unsigned NSIS packages on top of SmartScreen.
  • Corporate machines with AppLocker or Software Restriction Policies may block the run entirely — that needs a local administrator, not a workaround.

Status

Code-signing the build requires a signing certificate, which the project does not currently hold. Reputation improves as more users download the same unmodified asset, so later releases of the same build tend to trigger fewer prompts.

Resolved in v1.0.1

Each of these was reported against v1.0.0 and is fixed in the current release. Update to Desktop-Organizer-Setup-v1.0.1.exe to get them.

  • Download completion detection — files still transferring are no longer treated as finished.
  • .crdownload protection — Chrome temporary downloads are never moved.
  • .part protection — partial downloads from browsers and download managers are skipped.
  • .tmp protection — scratch and temporary files stay where their application expects them.
  • Notification spam — repeated toasts from a single run are deduplicated.
  • Startup issues — the logon registration path is reconciled instead of left stale.
  • Duplicate safety — candidates are re-checked before a Recycle Bin move.
  • OrganizerLibrary routing — files reach the intended category folder in the central library.

Real-time monitoring, folder-local organization, tray stability, installer reliability and overall release quality were improved in the same pass; see the changelog for the full list.

Being watched

Behaviours that are not bugs, but that surprise people often enough to list.

  • The tray icon can be hidden. Windows puts new tray icons in the overflow area. Drag the Desktop Organizer icon onto the visible bar once and it stays.
  • Closing the window does not stop organizing. The app keeps running in the tray; use Quit Desktop Organizer to stop it for real.
  • Newly created files wait before being filed. The stabilization and download completion delays (Settings → Monitoring) are deliberate — a file that is still growing is never touched.
  • OneDrive placeholder files. Cloud-only files may be skipped or trigger a download depending on your Windows settings; keep the placeholder materialized if you want it organized.
  • Antivirus false positives. Unsigned installers that write to a user profile can be quarantined by aggressive scanners. Restore the file and add an exclusion if that happens, and tell us so the detection can be challenged.
  • Web fonts require network. This website loads fonts from a CDN; with no connection the pages still render in a system fallback font.

How to report an issue

  1. Open Settings → Diagnostics and copy the version snapshot.
  2. Note what you expected, what happened, and which folder was involved.
  3. Attach the relevant lines from the monitoring log in Settings.
  4. File it on the issue tracker, checking first whether it is already open.

If a run moved something you did not want moved, undo it from Organization History first — then report it, including the run so the cause can be traced.
